# Offline deployment, redeployment and safe rollback runbook

**Status: specification only. There is no release installer, artifact signing, trust-root verifier, migration tool, or updater in this repository. Do not treat these steps as a completed deployment procedure.**

## Design rule

A legacy installation must be redeployable from an audited USB/removable bundle with no inbound Internet, without changing protocol trust or putting organizational private keys in the package. Distinguish recoverability from authenticity: **a SHA256 checksum alone does not authenticate the publisher**.

## Proposed release bundle

```text
rusti_rc-vX.Y.Z-<target-triple>/
  bin/                              # target-specific executable
  config/example.toml               # no secrets, disabled by default
  metadata/manifest.json            # version, target, ABI, min OS, build commit, digest
  metadata/manifest.json.sig        # detached signature, trusted verifier pending
  metadata/sbom.spdx.json           # dependency provenance
  metadata/build-provenance.json    # build environment and source digest
  docs/NOTICE-and-licenses/        # upstream notices when licensed
  docs/DEPLOYMENT.txt
```

Archive extraction, manifest parsing, signature verification, symlink swaps, portable config and rollback are **not implemented**. The manifest schema must be versioned and reject unknown security-critical fields.

## Operator procedure, after signing and verifier implementation

1. **Prepare** on a trusted build system: commit Cargo.lock generated by Cargo, run `cargo test --workspace --all-targets --locked`, lint/fuzz/audit and produce per-target binaries using documented compiler/sysroot/target flags. Never use `target-cpu=native` for distributable baseline builds.
2. **Release** only after independent security and licensing review: generate SBOM/provenance; sign the exact manifest and payload digests with release credentials isolated from ordinary CI/build steps; record the signed release metadata and revocation instructions.
3. **Stage** using separate trusted removable media; copy only signed bundles and public trust metadata. Do not copy live organization keys, peer journals, message history or credentials.
4. **Verify on recipient** with a preinstalled trusted verifier and pinned root: signature, trusted key epoch, target architecture/OS ABI, artifact hashes, supported feature/capability set, date/time/expiry policy, minimum allowed security version and path safety.
5. **Protect state** by backing up/migrating an approved versioned data store outside the application installation directory. Integrations must use Rust Boy's existing `PIPBOY_HOME` ownership and locks; never reset journals silently.
6. **Stage/activate** with an atomic platform-appropriate slot/pointer switch, while the service is stopped. Avoid direct in-place replacement of a running binary. No elevated permissions beyond those necessary for a controlled installation.
7. **Smoke test** offline before use: start with network disabled, verify configuration permissions, zero listener on import, supported target/CPU instruction set, logs with no secrets, and operator-visible connection/security status.
8. **Rollback** only if a previous slot is still signed, compatible with the state schema and **at or above the independently stored minimum-safe release version**. Do not roll back a security patch because the old binary happens to start.
9. **Record receipt**: host and hardware profile, verifier result, bundle digest, release and schema versions, operator approval, time source and failure/rollback result. Avoid logging sensitive messages/addresses.
10. **Retire/revoke** keys and unsafe releases through authenticated offline signed metadata; disconnected devices require an explicit controlled refresh protocol. A device that cannot obtain fresh trust metadata should fail closed where authentication freshness is mandatory.

## Operational failure cases and recovery

| Failure | Safe expected behavior | Recovery gate |
|---|---|---|
| No Internet | No network access needed for bundle verification if valid trusted metadata/time available | Use preloaded verifier and signed bundle |
| No RTC / stale clock | Never silently ignore certificate or metadata expiration | Obtain authenticated time/approved offline attestation or defer network auth |
| Replaced or truncated USB payload | Signature/digest or metadata check fails before activation | Quarantine bundle and source new signed copy |
| Wrong CPU, ABI, glibc, Windows version | Installer refuses wrong target, remains on last known-good slot | Select compatible tested artifact; never force execute |
| Insufficient disk / power failure | Preserve previous signed slot and immutable state; no partial migration | Check disk/SD integrity, replay only idempotent migration |
| Corrupt journal or config | Preserve forensic copy, refuse destructive reset | Recover from authenticated backup |
| Release revoked / below security floor | Block activation including rollback to vulnerable version | Install current safe release or isolate device |
| Credential loss / compromise | Do not ship credentials in binaries; re-enroll via controlled device trust workflow | Operator-admin recovery; never share private keys |
