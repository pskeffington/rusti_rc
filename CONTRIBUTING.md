# Contributing to rusti_rc

Contributions are welcome as focused, reviewable modules, but **no feature is approved for field deployment merely because it compiles**.

## Core rules

1. Keep all `crates/rusti-*` modules dependency-light, default inactive, `#![forbid(unsafe_code)]`, and Rust 2021-compatible; current MSRV target is 1.70. Any MSRV increase requires a documented compatibility assessment.
2. Every parser, transport, certificate, key-store, listener, or installer change needs its own threat model and negative tests. Include malformed, oversized, unsafe, disconnected, old-system and rollback cases as appropriate.
3. Keep untrusted IRC fields separate from Rust Boy identities. Do not link nickname/account/channel to Vault Command, tasks, jobs, assignments or peer trust.
4. Do not copy code from other IRC projects without recording the exact commit, license, attribution, and compatibility with this repository's MIT license.
5. No new network I/O, background polling, public bind, credentials, DCC, file upload or auto-discovery in a crate initializer. Explicit operator opt-in remains mandatory.
6. Do not weaken TLS/certificate validation for old machines. Use a separately reviewed, isolated gateway if a device cannot meet security requirements.
7. Add unit/property/fuzz tests and reproducible toolchain/per-target evidence; runtime hardware claims must show real measurements and device model/OS/ABI.
8. Keep release bundle signatures, trust-root provisioning, metadata expiry, version floors, backup, migration and rollback independently reviewed. Do not add an unsigned 'emergency' shortcut.
9. Keep tests and fixtures synthetic. No operator journals, location records, user credentials, PHI, tokens or host keys committed or printed.
10. MIT licensing is now documented in [LICENSE](LICENSE). Keep `publish = false` until API, CI, security, dependency provenance, and release controls have been reviewed. A license is not a release approval.

## Rust formatting and cleanup

Before opening a pull request, run the pinned formatter against each independent
Rust workspace (portable, modern TLS, and fuzz). These commands **check only**:

```sh
cargo +1.90.0 fmt --all --manifest-path Cargo.toml -- --check
cargo +1.90.0 fmt --all --manifest-path net/Cargo.toml -- --check
cargo +1.90.0 fmt --all --manifest-path fuzz/Cargo.toml -- --check
```

To apply formatting during development, omit the trailing `-- --check`,
review the resulting diff, and rerun all relevant tests. The machine-index
workflow enforces formatting on pull requests without write permissions.

Changes to CAP or SASL registration must preserve the shared fail-closed
`run_registration_once` guard and include TLS positive, rejection, cancellation
and no-downgrade tests. Formatting alone is not behavioral validation.

## Development smoke

```sh
cargo test --workspace --all-targets
cargo run -p rusti-standalone-cli
```

The tests are offline and the CLI smoke does not connect to any server. Verify against Rust 1.70 as well as stable; the GitHub CI workflow is the automation scaffold.

Review [compatibility](docs/deployment/LEGACY_COMPATIBILITY.md), [integration](docs/integration/RUST_BOY_ADAPTER_CONTRACT.md) and [release checklist](docs/security/RELEASE_CHECKLIST.md).

## Machine navigation upkeep

Routing and module ownership live in [index/catalog.json](index/catalog.json); generated [machine JSON](index/MACHINE_INDEX.json) and [docs/INDEX.md](docs/INDEX.md) should never be edited manually. When adding, renaming, or moving a tracked file, or changing source ownership, run:

```sh
python3 scripts/repo_index.py --write
python3 scripts/repo_index.py --check
python3 scripts/repo_index.py --path crates/rusti-proto/src/sasl.rs
python3 -m unittest discover -s scripts/tests -p 'test_repo_index.py' -v
```

Stage new files before running the generator: the index intentionally enumerates Git-tracked paths rather than untracked local work or generated bytecode. The index CI runs on every PR. It rejects stale output, dangling route targets, new unowned directories and secret-like file paths. Treat its routing hints as **navigation only**, never as authority to override [SECURITY.md](SECURITY.md) or assert production readiness.
